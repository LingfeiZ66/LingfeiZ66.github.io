Designing for Trust: Human–Human Interface (HHI)

What changes when an interface doesn't just control a device — but another person's body?

Designing a multi-user mobile experience where usability directly impacts safety.

Context & Problem

This project was part of a capstone collaboration with Backyard Brains, a company developing the Human–Human Interface (HHI), a neuroscience device that allows one user to stimulate another person's muscles through electrical signals. At the start of the project, the client only had a physical device designed for in-person demonstrations. However, their goal was to:

Enable two users to connect remotely through a mobile app and complete the experiment together.

Project Scope

Our team focused on designing the core interaction system that makes this possible:

  • Connecting the device to a mobile app
  • Connecting two users remotely
  • Supporting a complete end-to-end experiment flow

This includes:

  • pairing devices
  • guiding setup
  • coordinating actions between users
  • ensuring safe interaction

Why This Problem Is Different

This is not just controlling a device — it is controlling another person's body. The interaction combines:

  • physical systems (electrical stimulation)
  • social interaction (two users coordinating)
  • technical complexity (device + app + connection)

In this system, usability is not about efficiency — it is about trust and safety.

Key Insights → Design Responses

1. Safety & Consent Are Foundational

Users perceived the interaction as acting on another person's body, leading to hesitation and repeated confirmation behaviors.

Design Response

  • Shared "I'm Ready" confirmation
  • Consent checkpoints
  • Emergency stop
Outcome: Users feel safe and in control

2. Users Lack a Clear Mental Model

Users were unsure whether they were connecting to a device or another user, and how the system worked.

Design Response

  • Session-based system
  • Defined roles (Controller / Minion)
  • Role-first flow
Outcome: Clear understanding of system structure and responsibilities

3. System Feedback Is Insufficient

Users relied on guesswork to interpret system state.

Design Response

  • Real-time status indicators
  • Step-by-step setup feedback
Outcome: Improved confidence and reduced errors

Design Direction

We reframed the problem from device interaction to a human-to-human coordination system. Design principles:

  • Clear Setup
  • Shared Awareness
  • Consistent Feedback

Solution Overview

We designed a session-based mobile system that enables:

  • device-to-app connection
  • user-to-user connection
  • coordinated experiment flow

The system guides users step by step from: connection → setup → readiness → experiment

Impact & Broader Contribution

Education

Transforms the HHI device into a guided, teachable system:

  • reduces setup friction
  • improves learning experience
  • supports classroom and remote use

Future Potential (Health & Assistive Tech)

This work suggests potential for assistive interaction systems, such as supporting mobility-related use cases through safe, coordinated stimulation.
